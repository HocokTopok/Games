# Tank Wars / Nightfall

Игра по заданию из `promt.md`: C++23, SFML 3, CMake. Исходники находятся в `Tanks`.

## Сборка на macOS / Apple Silicon

Нужны Xcode Command Line Tools и CMake. Если их ещё нет:

```sh
xcode-select --install
brew install cmake
```

Из корня этого репозитория:

```sh
cmake -S Tanks -B Tanks/build -DCMAKE_BUILD_TYPE=Release
cmake --build Tanks/build --parallel 8
./Tanks/build/tank_wars
```

Также создаётся `Tanks/build/TankWars.app`: его можно открыть двойным щелчком в Finder или командой `open Tanks/build/TankWars.app`. Ресурсы и конфигурация включены внутрь приложения.

Первая конфигурация скачивает SFML **3.0.2**, FreeType и библиотеки Ogg/Vorbis/FLAC для аудио. Повторная сборка использует локальные зависимости. Если SFML 3 уже установлен, CMake использует его. Шрифт включён в репозиторий; графика, анимация и эффекты рисуются программно. Интернет во время игры не нужен.

## Начать играть

- **Play** — выбор оружия и карты, затем одиночная тренировка против бота Sentinel; меню действительно ставит такой бой на паузу.
- **Host** — создать комнату. Передайте другу показанные IP и порт.
- **Join** — ввести адрес хоста, например `192.168.1.12:53000`.
- В лобби каждый выбирает оружие и нажимает **Confirm weapon**. После подтверждения обоих игроков хост выбирает одну из четырёх карт; начинается бой. **Play** открывает такой же выбор перед тренировкой с ботом.
- Матч проходит одновременно для всех игроков. Победитель или команда определяются после уничтожения соперников и завершения полёта оставшихся снарядов. Активные небесные лучи также должны завершиться до подведения итога. Взаимное уничтожение даёт ничью.
- В сетевом матче Esc открывает локальное меню; бой на сервере продолжается. Кнопка **Play again** у хоста возвращает всех в лобби для нового подтверждения готовности.

Оба компьютера должны быть в одной локальной сети. Разрешите входящие подключения игре на компьютере хоста, если macOS запросит доступ.

### Два экземпляра на одном Mac

В первом терминале:

```sh
./Tanks/build/tank_wars --host
```

Во втором:

```sh
./Tanks/build/tank_wars --join 127.0.0.1
```

Каждое окно управляет своим танком, когда находится в фокусе. Отдельные комнаты могут использовать разные порты:

```sh
./Tanks/build/tank_wars --host --port 53001
./Tanks/build/tank_wars --join 127.0.0.1:53001
```

Для четырёх игроков: `--host --players 4`. Матч начинается при готовности всех подключённых игроков, минимум двух; `--players` задаёт вместимость комнаты. Для команд установите `teams = 1` в конфигурации хоста: игроки 1/3 и 2/4 образуют команды. Урон по себе и союзникам включён.

## Управление

| Действие | Управление |
|---|---|
| Движение | A / D |
| Мощность | W / S или колесо мыши |
| Прицел | Мышь |
| Выстрел | Space; удержание стреляет после перезарядки |
| Прыжок / полёт второго игрока | ↑: короткое нажатие — прыжок, удержание — набор высоты |
| Снижение второго игрока | ↓; без тяги танк опускается под действием гравитации |
| Меню / пауза | Esc |
| Счётчик FPS | F3 |
| Отключить / включить звук | M |
| Следующая композиция | F7 |

Белый пунктир показывает траекторию до первого столкновения, учитывая землю и танки. Другие игроки эту линию не получают. Поворот ствола ограничен скоростью башни, поэтому прицел отражает текущий угол пушки. После выстрела отойдите от ожидаемого места взрыва: близкие взрывы наносят урон и стрелявшему.

Камера показывает весь мир: на больших картах танки и снаряды выглядят меньше. Декоративные солдаты и дальние взрывы не наносят урона. Поверхность состоит из разрушаемого грунта и почти ровного каменного основания. Повторные попадания мортиры постепенно убирают холм до основания; остальные выбранные оружия рельеф не меняют. Новая партия восстанавливает карту.

Каждые **30 секунд** появляется транспортный самолёт. Он сбрасывает ящик на парашюте в случайную точку между 25% и 75% длины карты. После посадки ящик открывается, над ним вращается и покачивается подсвеченная иконка:

- Зелёный крест — **+200 HP**, до максимального здоровья.
- Оранжевый меч — **×1,5 урона на 15 с**. Повторное получение обновляет время, множители не складываются.
- Синий щит — **полная защита на 10 с**, включая взрывы, огонь и приземление другого танка.

Для получения нужно подъехать к ящику. Под полоской HP отображается цветной круг с оставшимся временем; лечение отмечается короткой зелёной вспышкой. Положение самолёта, тип и состояние ящика, усиления, повреждение карты и урон определяет сервер.

**Оба компьютера должны использовать 1.5.0.** Сборка создаёт обновлённый `Tanks/build/TankWars.app`; уже открытое старое приложение нужно закрыть и запустить новый файл. Версия указана в заголовке окна, в главном меню и по `--version`. Старые клиенты получают сообщение об обновлении при подключении к новому лобби. Базовый протокол старых версий сохранён для режима без выбора оружия, но старые сборки не поддерживают новые карты, усиления и весь набор оружия.

## Настройка

В **1.5.0** сервер передаёт полные типы снарядов, рикошеты, параметры взрывов, огонь и рельеф каждому клиенту. Клиент дополнительно сохраняет события между сетевыми обновлениями и кадрами отрисовки, чтобы короткие эффекты не терялись при получении нескольких снимков за кадр. Это устраняет путь, при котором согласование возможностей оставляло снаряды обычными белыми точками. **F3** показывает `PROJECTILE FX / FULL`, когда данные новых эффектов получены. Версия видна в заголовке окна и по `--version`. Для одинаковой графики запустите обновлённый `.app` у обоих игроков; старые исполняемые файлы не получают новую отрисовку автоматически.

Исходная конфигурация: [`Tanks/config/game.cfg`](Tanks/config/game.cfg). CMake копирует её и ресурсы к исполняемому файлу. При обычном запуске читается `Tanks/build/config/game.cfg`; после следующей сборки эта копия обновляется из исходника. Для собственных настроек удобно передать отдельный файл:

```sh
./Tanks/build/tank_wars --config Tanks/config/game.cfg
```

В конфигурацию вынесены размеры мира, рельеф, физический шаг, гравитация, параметры танков и пушки, урон, радиус взрыва, перезарядка, частоты сети, команды, вместимость комнаты и окно. Ошибочные значения и неизвестные ключи останавливают запуск с пояснением. В сети клиент получает игровые параметры от сервера.

**Settings** управляет тряской камеры, частицами, пунктирным прицелом и пределом FPS (60 / 120 / без ограничения). Эти визуальные настройки действуют до закрытия игры.

В **Settings** отдельно регулируются **Sound effects** и **Music**. У мортиры есть тяжёлый выстрел, свист падающего снаряда и низкий взрыв с хвостом; у сферы — энергетический запуск, гул, металлические рикошеты и разряд. Полёт сопровождается реактивной тягой, движение — звуком гусениц, огонь — треском. Звуки располагаются по стереопанораме относительно вашего танка. Нумерованные события не звучат повторно при получении одинаковых сетевых снимков. Микшер ограничивает суммарную громкость, а крупные взрывы временно приглушают музыку. При потере фокуса звук плавно затихает.

Музыкальный плейлист: **Nihilist — Sentenced to Death**, затем **DJ Asul — MATADORA**, по кругу. Записи находятся в `Tanks/assets/music` и копируются внутрь `.app`. Порядок и отображаемые названия задаёт `playlist.m3u`; дополнительные MP3/OGG/FLAC/WAV в этой папке добавляются автоматически. **F7** переключает трек с плавным затуханием. **M** отключает весь звук; настройки громкости сохраняются до закрытия игры. Интернет для воспроизведения не требуется. Эффекты синтезируются самой игрой и не требуют отдельных аудиофайлов.

## Проверки

```sh
ctest --test-dir Tanks/build --output-on-failure
```

- `missile` проверяет наведение на первое препятствие, ограничение поворота, урон, щиты, усиление, перезарядку и новые профили карт.
- `missile_network` проверяет настройки ракеты по TCP, направленный взрыв и совпадение графики двух клиентов; сохраняет кадры ракеты и четырёх карт во временной папке системы.
- `arsenal` проверяет три отскока от земли и склона, ограничение числа отскоков, непрерывные столкновения, прямой урон мортиры, постепенный урон небесного луча, предупреждение, щит, усиление урона и уход из зоны.
- `arsenal_network` проверяет передачу всех настроек фаера и активной колонны двум TCP-клиентам, точный суммарный урон, истечение луча, одинаковые кадры Host/Join и сохраняет `tankwars-arsenal-fx.png` во временную папку системы.
- `battlefields` проверяет выбор оружия и карты, четыре масштаба, плавные кратеры и неразрушаемое основание, баллистику рикошетов, ограничения разрушения, щит, все три усиления и их истечение.
- `battlefield_network` проверяет авторитетный выбор по TCP, сравнивает отрисовку Host/Join попиксельно, проверяет огонь, кратеры, управляемые ракеты, рикошеты и полный первый цикл доставки ящика (около 45 с). Для него нужен доступ к графике и loopback-сокетам.
- `simulation` проверяет симметрию карты, интегрирование, непрерывные столкновения, совпадение прогнозируемого и реального попадания, взрывной урон, готовность, перезарядку, завершение матча и четыре места игроков.
- `controls` проверяет движение, мощность и стрельбу через события клавиатуры, удержание без автоповтора, отпускание и сброс ввода при потере фокуса. Используются физические клавиши независимо от раскладки; глобальный опрос клавиатуры не нужен.
- `mechanics` проверяет квадратичный урон и рост сферы, оба рикошета и третье касание, углы карты, непрерывные попадания, дугу мортиры, радиус взрыва, прыжок, полёт и снижение.
- `audio` проверяет уровни всех звуков, отсутствие клиппинга и резких границ, циклические эффекты и разные тембры оружий.
- `graphics_protocol` проверяет передачу сферы, мортиры и параметров взрыва двум TCP-клиентам с отсутствующими или неполными флагами возможностей; запускается при наличии Python 3.
- `titan` проверяет 1000 конечных HP у обоих игроков, убывание здоровья и масштаб полоски, мгновенный лазер, смертельное приземление сверху и победу.
- `stomp_network` выполняет взлёт, перелёт и смертельное приземление через настоящий TCP-сервер и проверяет одинаковый результат у обоих клиентов.
- `network` запускает настоящий сервер на свободном loopback-порту и два клиента без графики. Проверяет handshake, синхронизацию конфигурации и событий, лобби, движение, просроченный ввод, отключение и реванш.

Дополнительный исторический тест старого протокола (только режим `loadout_selection = 0`; для новых карт и оружия используйте 1.5.0 на обоих компьютерах):

```sh
python3 Tanks/tests/check_legacy_compatibility.py --ref 6132487
python3 Tanks/tests/check_legacy_compatibility.py --ref 8e2d8ce
```

Скрипт компилирует старые исходники во временном каталоге и проводит два смешанных матча. Основной рабочий каталог остаётся на текущей версии.

Автоматический запуск графики и снимок последнего кадра:

```sh
./Tanks/build/tank_wars --demo --map 3 --frames 180 --screenshot /tmp/tank-wars.png
```

## Устройство проекта

| Компонент | Назначение |
|---|---|
| `Game` | Окно, события, состояния меню, ввод, фиксированный цикл |
| `GameSession` | Лобби, игроки, команды, бот, победа, реванш |
| `World` | Авторитетное обновление танков, снарядов, урона и событий |
| `Map` | Четыре карты, поверхность, кратеры, неразрушаемое основание и болотные участки |
| `Types` / `Weapon` | Модель танка и снаряда; данные пушки и создание выстрела |
| `Physics` | Общая баллистика, swept-столкновения и прогноз траектории |
| `Renderer` | Иерархия деталей танка, гусеницы, UI, следы, кольца, частицы, камера |
| `Network` | TCP-сервер, клиент, ограниченные очереди пакетов, интерполяция |

Симуляция независима от графики и сети. Физика обновляется с шагом 1/120 с; сервер отправляет 30 снимков/с, клиент интерполирует с задержкой 75 мс. Хост использует тот же сетевой клиент, что и остальные игроки. Команды содержат движение, угол, изменение мощности, стрельбу и вертикальную тягу; здоровье, попадания и победу определяет сервер. Устаревший ввод обнуляется, потерявший соединение игрок уничтожается. Эффекты подписываются на нумерованные события и не проигрываются повторно при повторении снимка.

Для новой карты расширьте `MapFactory` и профиль `Terrain`. Снимок содержит отсчёты поверхности с шагом 4 единицы; клиент использует их и для картинки, и для прицела. Баланс пушки задаётся `WeaponSpec`; создание снаряда находится в `Weapon.hpp`, а новые законы движения можно добавить рядом с общим интегратором `Physics`. Новые эффекты добавляются по типам `GameEvent`. Количество игроков ограничено четырьмя в модели и протоколе, без отдельных веток логики для второго игрока.

Отдельный сервер без окна:

```sh
./Tanks/build/tank_wars --server --port 53000 --players 4
```

Первый подключившийся игрок управляет реваншем. `--seconds N` завершает сервер через N секунд; все параметры перечислены в `--help`.

## Windows и Linux

Симуляция и графика используют переносимый C++23 и SFML. Сетевой поток использует `std::thread`, `<atomic>` и явный `join()`; поддержки `std::jthread` / `std::stop_token` от Apple libc++ не требуется. На Linux предварительно установите системные зависимости SFML (X11, Xrandr, Xcursor, Xi, udev, OpenGL и FreeType). На Windows используйте Visual Studio 2022 с C++23 и CMake: `cmake -S Tanks -B Tanks/build`, затем `cmake --build Tanks/build --config Release`; исполняемый файл будет в `Tanks/build/Release`. На этих ОС требуется отдельно проверить сборку и графический запуск.

Шрифт Rajdhani — SIL Open Font License, текст лицензии находится в `Tanks/assets/fonts/OFL.txt`. SFML — zlib/png; FreeType — FreeType License или GPLv2, лицензии входят в загружаемые исходники зависимостей.
